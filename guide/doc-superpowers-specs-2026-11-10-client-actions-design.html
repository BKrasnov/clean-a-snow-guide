docs/superpowers/specs/2026-11-10-client-actions-design.md

Клиент: одна дверь к серверу

Карточка ca847e. Решение владельца 10.11.2026: спека утверждена, сад входит. Основание: решение владельца 10.11.2026 — кандидат A разбора клиента 7e9ffc (docs/architecture/client-view.html) и сводка dc68a4. По сводке карточка включает кандидата B разбора сети (сад через ActionRequest) и две мелочи сети.

Что сейчас не так

Где Что делает
Bootstrap.client send Проверяет пакет по NetSchema, ставит кнопке Pending, ждёт ответ 8 с, просит Resync. Ответ раздаёт тремя ручными вызовами (referenceSnow.result, weapons.result, ui.result). Всё это внутри функции запуска, без теста.
SnowMatchHud.collectNearby Раз в 0.4 с сам шлёт ActionRequest PickupNearby, мимо send: без проверки схемы и без ожидания ответа.
InterfaceController.result Гасит «обычные» отказы для ответов без вида запроса: это ответы на автоподбор из SnowMatchHud.
GardenController и GardenService Свой Remotes.Garden: ни схемы, ни лимита роутера, ни requestId, ни ответа. Отказ в покупке семян игрок видит как сырой код (InsufficientFunds) в плашке сада.
NetSchema.LeaderboardPage Пускает 4 метрики, ExtrasService отвечает только на 2.
Throw Вид пакета в схеме и роутере, который всегда отвечает ThrowDisabled; клиент его не шлёт.

Модуль Actions

src/ReplicatedStorage/CleanSnow/Shared/Actions.luau, --!strict. Работает только на клиенте; лежит рядом с NetSchema, потому что в тестовом плейсе нет клиентской папки.

Actions.new(deps) -> Actions
-- deps: fire(envelope), validate(kind, payload) -> (ok, code), guid() -> string, clock() -> number,
--       revision() -> number?, refused(kind, code)
actions.send(kind, payload, button?) -> string?   -- requestId или nil
actions.receive(result)                           -- ответ сервера из ActionResult
actions.listen(fn(result, kind?)) -> () -> ()     -- каждый ответ с видом своего запроса
actions.onTimeout(fn(kind)) -> () -> ()
actions.step()                                    -- раз в кадр: тайм-ауты
Actions.publish(actions); Actions.await() -> Actions   -- общий экземпляр для отдельных LocalScript

Внутри то, что сейчас лежит в Bootstrap.client:

  • проверка схемы; при отказе пакет не уходит, refused показывает плашку;
  • Resync не чаще раза в секунду, с knownRevision из revision();
  • Pending на кнопке на время ожидания;
  • нет ответа за 8 с — onTimeout и Resync;
  • ответ RevisionMismatch или StaleRevision — Resync.

Bootstrap.client создаёт Actions, вешает ActionResult на receive, подписывает снег, оружие и окна через listen, а ui.requestTimedOut — через onTimeout. Поведение для игрока не меняется.

Кто переходит

  • SnowMatchHud: автоподбор шлёт через send (его передаёт MapSnowController из своих зависимостей). Интервал 0.4 с и радиус не меняются, ручной подбор в ExperienceController остаётся как есть. Других FireServer в ActionRequest в клиенте не остаётся.
  • InterfaceController.result: ответ без вида теперь значит только «опоздал после тайм-аута». Правило тишины то же, комментарий меняется.
  • Сад, сервер:
    • Remotes.Garden удаляется;
    • пять видов пакета в NetSchema со своими лимитами: GardenBuy {seed}, GardenSell {}, GardenWork {point}, GardenInventory {}, GardenEquip {seed, harvest};
    • обработчики в списке действий RuntimeFactory при layout.runs зовут ctx.garden.request(id, kind, payload), а тот возвращает результат;
    • GardenBuy и GardenSell возвращают ответ кошелька, при отказе плашка не пишется;
    • остальные виды возвращают OK, их подсказки идут плашкой, как сейчас;
    • сообщения сервера саду (Notice, Inventory, Shop, SeedFound, Worked) идут через ctx.emit как WorldEvent с видами GardenNotice и так далее.
  • Сад, клиент: GardenController остаётся отдельным LocalScript. Он берёт Actions.await() и шлёт виды Garden*, а сообщения читает из WorldEvent по видам Garden*.
  • NetSchema.LeaderboardPage: метрики snowCleared и coinsEarned, как отвечает сервис.
  • Throw удаляется из схемы и роутера.
  • Вождение машины (VehicleDrivingInput) и DevPanel не меняются.

Что увидит игрок

  • Подбор снега, удары, магазин — как сейчас.
  • Нет лишних «Please wait a moment» после автоподбора.
  • Семена при нехватке монет: вместо сырого кода — та же реакция, что у магазина. Продажа урожая и грядки — те же плашки сада.

Проверка

Тест до кода, tests/ServerStorage/UnitTest/Cases/Actions_Test.luau, на подставном fire и часах:

  1. Пакет вне схемы не уходит, refused получает код.
  2. Ответ доходит до подписчика с видом своего запроса, Pending у кнопки снимается.
  3. Нет ответа 8 с — onTimeout с видом и один Resync.
  4. Ответ RevisionMismatch — Resync; второй Resync в ту же секунду не уходит.

Дополнить NetSchema_Test: у пяти видов сада есть лимит; LeaderboardPage с метрикой runs не проходит; Throw неизвестен.

Потом npm run check, npm run test:game -- Actions, -- NetSchema. Play в своём окне (npm run play -- window):

  • автоподбор снега;
  • покупка в магазине;
  • семена: покупка без монет и с монетами;
  • грядка в саду.
